## 1. 目的と最上位絶対原則（Supreme Principles）

本規程は、Universal POSTING MAP における新地区展開（プロビジョニング）およびマスターデータ（`address_master.csv`, `boundaries.geojson`）の生成において、**「人間によるデータ取得作業の完全排除（ゼロ手作業）」** と **「複数公定データ結合による高解像度完成住所の確立」** を担保するための標準実行規範である。

### 【原則 1】ゼロ人間介入の原則（Zero Human Intervention）— ABSOLUTE
- 地区マスターの生成に必要な公定一次資料（国交省位置参照情報、e-Stat国勢調査データ等）の調達は、**100% AIエージェントが自律スクリプトにより実行**しなければならない。
- ユーザー（人間）にブラウザでダウンロードさせたり、フォルダーへの配置を指示・依頼することは**永久に禁止**する。
- 自治体コード（市区町村コード5桁）を指定するだけで、すべての調達・解凍・検証が完全自動で完結しなければならない。

### 【原則 2】2段階データ結合原則（Two-Stage Data Synthesis Doctrine）— ABSOLUTE
マスターデータは単一のデータソースから安易に生成してはならない。必ず以下の順序で結合・合成する。
1. **第 1 段階（住所・地名基盤 SSOT）**:
   - 国土交通省「街区レベル位置参照情報」を調達。
   - 「大字」接頭辞を完全に排除し、町名本体、小字名（字・通称名）、街区・地番ポイントを確定する。
2. **第 2 段階（境界線・統計合体 SSOT）**:
   - 総務省統計局「e-Stat 令和2年国勢調査小地域境界データ」を調達。
   - 境界ポリゴン、実測人口（`JINKO`）、実測世帯数（`SETAI`）、小地域コード（`KEY_CODE`）を取得。
3. **空間結合（Point in Polygon）**:
   - e-Stat境界ポリゴン内に第1段階のポイント群を空間結合し、大字重複エリアに小字名や代表地区名を動的結合する。

### 【原則 3】動的完成度判定原則（Address Completeness Doctrine）— ABSOLUTE
- `docs/architecture/ADDRESS_EXTRACTION_RULE.md`（岩佐CEO策定）に基づき、取得した町名文字列が粗い（大字のみで複数小地域に分割されている等）場合、第2階層（小字・地区名）を結合して **`江場（中野）`** のような一意かつ直感的な「完成住所」として確定する。
- `大字江場` のような同名レコードが重複してマスターCSVに並ぶ状態を**手抜き未完成データ**として厳格に排除する。

## 3. 調達データソース仕様と自動化要件

### データソース A: 国土交通省 街区レベル位置参照情報
- **提供元**: 国土交通省 国土数値情報（位置参照情報ダウンロードサービス）
- **対象バージョン**: 最新年度版（24.0a 等）
- **取得単位**: 市区町村別 ZIP（例: `24205-24.0a.zip`）
- **自動調達方法**:
  - 市区町村コードからダウンロードURLを決定論的に解決。
  - スクリプト（`scripts/fetch-district-raw-data.py`）により直接HTTP取得・解凍。
  - 文字コード: CP932（Shift-JIS） ➔ UTF-8 自動正規化。
  - キャッシュ配置先: `data/raw_reference/{市区町村コード}/`
- **抽出項目**:
  - 大字・町丁目名（※先頭の「大字」文字列を正規表現 `^大字` で機械的排除）
  - 小字・通称名（`koaza`）
  - 街区符号・地番（`chiban`）
  - 代表緯度・経度（`lat`, `lon`）

### データソース B: 総務省統計局 e-Stat 国勢調査小地域境界データ
- **提供元**: 政府統計の総合窓口（e-Stat）
- **対象調査**: 令和2年国勢調査 小地域（町丁・字等別境界データ）Shapefile（世界測地系JGD2000/2011）
- **取得単位**: 市区町村別 ZIP（例: `A002005212020DDSWC24205.zip`）
- **自動調達方法**:
  - e-Stat GIS API または固定公開エンドポイントより市区町村コード単位で自動取得。
  - キャッシュ配置先: `data/raw_estat_r2/{市区町村コード}/`
- **抽出項目**:
  - 小地域識別コード（`KEY_CODE` / `KCODE1`）
  - 境界ジオメトリ（Shapefile）
  - 実測人口（`JINKO`）、実測世帯数（`SETAI`）
  - 調査区属性（`HCODE`: 8101以外および「水面」「水域」は完全除外）

## 4. 2段階空間結合 & 完成住所命名ルール

### ルール 4.1: 単一町丁（1:1 対応エリア）
- e-Statの小地域コードが親町名と1:1で完全一致し、分割が存在しないエリア。
- **命名規則**: 大字を除外した町名本体を採用する。
  - 例: `大字上野` ➔ **`上野`**
  - 例: `大字和泉` ➔ **`和泉`**
  - 例: `相生町` ➔ **`相生町`**（変更なし）

### ルール 4.2: 分割大字（1:N 対応エリア）の動的解像度向上
- 単一大字が国勢調査上で複数の小地域（枝番 01〜N）に分割されているエリア。
- **命名手順**:
  1. e-Stat境界ポリゴン内に含まれる位置参照情報のポイント群を空間判定（Point in Polygon）。
  2. ポリゴン内に特定の小字（`koaza`）が優位に存在する場合:
     - ➔ **`町名（小字名）`**
     - 例: 江場 rowId 62（中野が64件集中） ➔ **`江場（中野）`**
     - 例: 江場 rowId 58（宮乃島が27件検出） ➔ **`江場（宮乃島）`**
  3. 小字が無表記で、地番が特定範囲に局所化している場合:
     - ➔ **`町名（方角）`** または **`町名（主要地番）`**
     - 例: 江場 rowId 59（北東端・地番7〜48） ➔ **`江場（北東部）`**
     - 例: 江場 rowId 60（北部） ➔ **`江場（北部）`**
     - 例: 江場 rowId 61（西部・1500番台） ➔ **`江場（西部）`**
- **アサーション**: 同一自治体内で完全一致する同一 `town_name` が複数行発生してはならない（重複ゼロ保証）。

### ルール 4.3: 日本語あいうえお順整列規則（読み順SSOT）
- 「大字」を排除した純粋な町名本体に基づき、日本郵便公定データからソート用カナ（`sort_kana`）を導出する。
  - 例: `江場（中野）` ➔ 読み `エバ（ナカノ）` ➔ **「エ」行**に整列。
  - （※旧ロジックのように「大字」がついていることで「オ」行に誤配置される歪みを根絶する）
- 既存の `rowId`（1..N）の数値そのものは100%保持し、絶対に改番・振り直しを行わない。

## 5. 品質保証ゲート（Verification Gates: QG-1 〜 QG-5）

マスター生成完了時、以下の5層ゲートをすべてPASSしなければデプロイ・本番反映を禁止する。

| Gate | 検証項目 | 合格基準 |
| :--- | :--- | :--- |
| **QG-1: 完全自律調達ゲート** | 人間介入ゼロの客観証明 | スクリプト単体実行で外部ZIP取得から配置までエラーなく完走すること。人間の手動操作が介在していないこと。 |
| **QG-2: 人口・世帯数突合ゲート** | e-Stat原本との完全一致 | 生成されたCSVの人口・世帯数合計値が、e-Stat原本DBFの合計値と**差分0**であること。 |
| **QG-3: 住所完成度・重複排除ゲート** | 未完成町名の根絶 | `town_name` に「大字」が含まれていないこと。同一自治体内の町名重複が0件であること。 |
| **QG-4: 参照整合性保護ゲート** | rowIdの完全性 | 既存 `rowId`（1..N）が1件の欠番・重複もなく保持されていること。 |
| **QG-5: 幾何トポロジーゲート** | GeoJSON正常性 | 境界ポリゴンの自己交差（Self-intersection）が0件、CRSがCRS84であること。 |

---

## 6. 禁止事項（Prohibited Actions）— ABSOLUTE

1. **手作業ダウンロードの要請**: ユーザー（人間）にデータ取得・ZIP解凍を指示すること。
2. **単一ソース横流し**: e-Stat等のShapefile属性（`S_NAME`）をそのままCSVに書き出して終了すること。
3. **無断改番**: 住所表記の改善に伴い、既存 `rowId` を勝手に振り直すこと。
4. **外部有料API依存**: Google Maps Geocoding API等の外部課金APIをデータ生成パイプラインの前提にすること（完全オフライン・オープンデータで完結させること）。
